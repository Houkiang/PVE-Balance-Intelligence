# 数据生成开发步骤

## 1. 目标

使用 Python 批量生成模拟游戏事件数据，解决真实大量玩家同时游玩不可实现的问题。模拟数据需要规模足够、结构稳定、规律可解释，能够支撑职业平衡、地图难点、卡牌强度和流派组合分析。

数据生成采用配置驱动方案：配置文件定义游戏规则和数值倾向，生成脚本只负责读取配置、执行模拟并输出日志。

## 2. 输入配置

建议先实现以下配置文件：

| 文件 | 作用 |
| --- | --- |
| `config/simulation_config.yaml` | 控制对局数、玩家数、日期、随机种子、50 波目标等全局参数 |
| `config/hero_config.csv` | 定义职业基础输出、生存、治疗、承伤定位、卡牌偏好 |
| `config/card_config.csv` | 定义卡牌类型、稀有度、强度、适配职业、成长数值 |
| `config/weapon_config.csv` | 定义武器基础数值、攻击方式、升级维度、成长曲线 |
| `config/map_config.csv` | 定义地图尺寸、危险区域、刷新密度区域 |

队伍人数固定为随机 `2-10` 人。地图采用 `1000x1000` 二维网格，坐标范围为 `0 <= x < 1000`、`0 <= y < 1000`。

配置和脚本职责边界：

| 部分 | 职责 |
| --- | --- |
| 配置文件 | 决定职业强弱、卡牌权重、武器成长、地图危险度和发卡规则 |
| 数据生成脚本 | 按配置执行批量模拟，不在代码中写死核心数值 |
| 输出日志 | 记录模拟过程，用于后续 PySpark 离线分析 |

## 3. 卡牌生成方案

卡牌分为五类：

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| `permanent_buff` | 永久属性 Buff | 增加力量、幸运、移速、防御 |
| `instant_effect` | 即时或短时效果 | 立刻回血、短时护盾 |
| `new_weapon` | 获得新武器 | 法杖、飞刀、火炮 |
| `weapon_upgrade` | 升级已有武器 | 伤害、每轮 CD、攻击次数、攻击频率、范围 |
| `global_affix` | 后期出现的带负面效果的全局词条 | 高额伤害提升但降低防御或移速 |

每张卡牌都有基础权重，但最终出现概率需要结合局内状态动态计算：

```text
final_weight =
  base_weight
* wave_phase_weight
* hero_affinity_weight
* build_synergy_weight
* prerequisite_weight
* rarity_weight
```

规则示例：

1. `weapon_upgrade` 只在玩家已经拥有对应武器后出现。
2. `global_affix` 只在后期出现，例如 `wave >= 35`。
3. 幸运属性提高高稀有卡牌出现概率。
4. 职业适配会影响卡牌出现概率，例如法师更容易看到法杖和范围伤害。
5. 已有流派标签会影响后续卡牌，例如已有 `aoe` 标签时更容易看到范围强化。

## 4. 卡牌选择方案

游戏是自动战斗，但玩家升级时仍需要选择卡牌。模拟玩家选卡时不要完全随机，建议使用评分模型：

```text
pick_score =
  base_card_value
+ hero_fit_score
+ build_synergy_score
+ survival_need_score
+ weapon_growth_score
- risk_penalty
+ random_noise
```

评分含义：

| 分数 | 说明 |
| --- | --- |
| `base_card_value` | 卡牌本身强度 |
| `hero_fit_score` | 与职业定位的适配程度 |
| `build_synergy_score` | 与已有卡牌、武器和流派标签的协同 |
| `survival_need_score` | 当前血量低或死亡压力大时，提高回血、防御等卡牌价值 |
| `weapon_growth_score` | 已有武器对应升级卡的成长价值 |
| `risk_penalty` | 负面词条带来的风险惩罚 |
| `random_noise` | 模拟玩家偏好差异，避免选择过于机械 |

这种方式可以让 `card_choice` 和 `card_pick` 数据既有随机性，又能体现职业、轮次、武器和流派影响。

## 5. 输出数据

原始事件输出为 JSON Lines：

```text
data/local_raw/game_event_log/dt=yyyy-MM-dd/events.jsonl
```

每行是一条事件，必须包含公共字段：

| 字段 | 说明 |
| --- | --- |
| `event_id` | 事件唯一 ID |
| `event_type` | 事件类型 |
| `event_time` | 事件时间 |
| `dt` | 分区日期 |
| `match_id` | 对局 ID |
| `room_id` | 房间 ID |
| `map_id` | 地图 ID |
| `player_id` | 玩家 ID，可为空 |
| `hero_id` | 职业 ID，可为空 |
| `wave` | 当前轮次 |
| `x`、`y` | 地图坐标，可为空 |
| `extra` | 事件扩展 JSON |

## 6. 必须事件

| 事件 | 作用 |
| --- | --- |
| `battle_start` | 标记对局开始 |
| `battle_end` | 标记对局结束和最终轮次 |
| `player_join` | 记录玩家、职业、队伍 |
| `wave_start` | 记录每轮开始 |
| `enemy_spawn` | 记录敌人刷新位置和数量 |
| `enemy_kill` | 记录击杀归属 |
| `level_up` | 记录升级行为 |
| `card_choice` | 记录候选卡牌，用于计算选取率 |
| `card_pick` | 记录最终选择卡牌 |
| `position_tick` | 记录玩家位置，用于停留时长和热力图 |
| `player_wave_stat` | 记录每名玩家每轮表现 |
| `player_death` | 记录玩家死亡位置和轮次 |

## 7. 玩家表现事件

`player_wave_stat` 的 `extra` 至少包含：

| 字段 | 说明 |
| --- | --- |
| `damage_dealt` | 本轮造成伤害 |
| `kill_count` | 本轮击杀数 |
| `heal_done` | 本轮治疗量 |
| `damage_taken` | 本轮受到伤害 |
| `support_score` | 护盾、控制、增益等辅助贡献，可先设为可选 |

承伤需要按职业解释：坦克承伤通常是贡献，但需要结合生存率；脆皮承伤过高通常是风险。

## 8. 生成逻辑

建议按以下顺序生成一局对局：

1. 生成 `match_id`、`room_id`、`map_id` 和开始时间。
2. 随机生成 `2-10` 名玩家和对应职业。
3. 初始化玩家属性状态、武器状态、卡牌集合和流派标签。
4. 根据职业基础能力、队伍组合和地图危险度计算初始队伍强度。
5. 逐轮生成敌人刷新、击杀、升级、卡牌候选、卡牌选择、位置采样和玩家表现。
6. 每次选卡后更新玩家属性、武器状态、临时效果或全局词条。
7. 根据当前玩家状态、武器状态、卡牌效果、地图危险区域和当前轮次决定表现与死亡概率。
8. 根据队伍最终状态输出 `battle_end`，并记录最终轮次。

## 9. 验收标准

1. 能生成至少 `1000` 局对局事件。
2. 同一随机种子下生成结果可复现。
3. 每局玩家数在 `2-10` 范围内。
4. `card_choice` 和 `card_pick` 能支撑卡牌选取率。
5. `position_tick`、`player_death`、`enemy_spawn` 坐标均在 `1000x1000` 地图范围内。
6. `player_wave_stat` 能支撑高表现率计算。
7. 修改配置文件即可改变职业强度、卡牌权重、武器成长和地图危险区域，不需要修改生成脚本核心逻辑。

## 10. 运行方式

数据生成完全由命令行手动控制，不会自动执行。

只查看生成计划，不写文件：

```bash
python scripts/generate_data.py --matches 1000 --players 300 --days 1 --start-date 2026-05-12 --dry-run
```

生成指定规模数据：

```bash
python scripts/generate_data.py --matches 1000 --players 300 --days 3 --start-date 2026-05-12 --overwrite
```

输出到指定目录：

```bash
python scripts/generate_data.py --matches 200 --players 80 --output-dir data/sample/generated_events --overwrite
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--matches` | 生成对局数量 |
| `--players` | 模拟玩家池大小 |
| `--start-date` | 起始日期 |
| `--days` | 生成多少个日期分区 |
| `--seed` | 随机种子，用于复现 |
| `--output-dir` | 输出目录 |
| `--overwrite` | 覆盖已有输出 |
| `--append` | 追加到已有输出 |
| `--dry-run` | 只打印计划，不写文件 |
